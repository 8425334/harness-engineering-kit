# {{PROJECT_NAME}} AI 开发约束

> **前端工程能力模型**：本项目遵循 [前端工程 4 铁律 + 组件分解模式](../../docs/methodology/core/frontend-engineering.md)。修改前端代码时自动触发 RADIR 工作流。

## 适用范围

- 当前目录及其全部子目录，除非更下层目录另有 `AI.md`。
- 本文档是根目录 `AI.md` 在前端项目上的细化版本。

## 目录职责

- `src/views`：页面与业务交互层，负责页面布局、表格、表单、页面级交互编排；复杂页面应拆到同目录 `modules/`，避免单文件膨胀。
- `src/service/api`：接口封装层，负责请求路径、参数、返回类型与面向页面的 API 方法；不承载页面状态和 UI 逻辑。
- `src/service/request`：统一请求实例、鉴权、拦截器、错误处理；不混入具体业务页面语义。
- `src/router`：路由定义；优先通过页面结构与路由生成工具维护。
- `src/store`：全局或跨页面共享状态；仅当状态确有跨模块复用价值时才进入 store。
- `src/components`：可复用组件；强业务语义组件优先放在对应页面的 `modules/`，避免过早全局化。
- `src/hooks`：可复用行为抽象；不要把只服务单一页面的一次性逻辑误下沉为全局 hook。
- `src/typings`：前后端契约映射；接口字段变化时必须与后端同步更新。
- `src/locales`：国际化文案与路由标题；新增页面、菜单或显式文案变更时需同步更新。

## 4 铁律

1. **分层不可逾越**：`views → api → request`，禁止越层调用
2. **类型即契约**：禁止 `any`，API 类型与后端同步，枚举不前端自造
3. **组件受控**：单文件 ≤ 300 行，弹窗/表单/表格独立组件，业务组件不过早全局化
4. **三态覆盖**：Loading / Empty / Error 必须处理，表单提交需提交中/成功/失败三态

## 组件分解规则

| 触发条件 | 拆分动作 |
|----------|----------|
| `v-if`/`visible` 控制的弹窗/抽屉 | 拆为 `modules/<name>-modal.vue` 或 `<name>-drawer.vue` |
| 表单字段 > 5 个 | 拆为 `modules/<name>-form.vue` |
| 表格列 > 6 列 | 拆为 `modules/<name>-table.vue` |
| 逻辑被 2+ 处使用 | 提取到 `hooks/` 或 `components/` |
| 文件 > 300 行 | 必须分解 |

## 质量门禁

- typecheck → build → gen-route（如适用）→ 4铁律自检
- 新增/修改页面需检查：路由注册、i18n 文案、权限编码
