# 上下文能力

上下文质量来自有界路由，而不是批量加载或重复规则。

## 两层上下文

| 产物 | 用途 | 硬边界 |
|---|---|---|
| 根 `ai.json` | 机器可读初始化地图 | 只含摘要和路由；不超过 4096 字节；不得放命令、权限、约束或详细规则 |
| 被索引的 `AI.md` | 人和机器可读的路径细节 | 职责、边界、不变量、依赖、入口、契约和局部验证；不超过 400 行 |

项目只有一个根 `ai.json`，且必须登记根模块（`path: "."`）。每个维护中的 `AI.md` 都必须在 `modules` 数组登记模块路径、简短摘要、精确上下文路径和 1–8 个 `read_when` 关键词。修改代码前，`resolve_context.py` 将全部任务路径和显式关键词解析为唯一加载顺序：策略、方法论 Profile、索引，再按父到子加载命中的详情。子级只记录局部差异，祖先上下文持续生效。两层都不能覆盖原生指令或 `agent-policy.yaml`。

缺少根路由、目标越出项目、显式关键词没有路由或任何已索引文档非法时，解析都会 fail-closed。路径选择包含目标的全部已登记祖先模块；关键词选择包含全部匹配模块及其已登记祖先。

## 更新契约

每个非微小变更都包含受审批绑定的 `context-impact.json`：

- `project-summary`、`module-topology`、`context-route`、`entrypoint` 强制更新 `ai.json`。
- `responsibility`、`boundary`、`invariant`、`dependency`、`contract`、`local-verification` 强制更新受影响的 `AI.md`。
- `none` 只能单独使用，且仍需分别说明两层为何不受影响。
- `analyzed_paths` 声明完整计划交付文件集合，Review 摘要必须与其完全一致。

`check_context_docs.py` 校验 Schema、大小、路径归属、索引完整性、详细文档结构和断裂引用；`resolve_context.py` 证明校验后的图能够生成可执行加载顺序。缺少必要上下文更新或未经审批的上下文更新时，`check_phase.py` 会阻断 Review。

信号选择属于受审批绑定的语义设计决策；确定性门禁负责校验映射与证据，但无法从任意代码中推断业务职责。审批人必须拒绝理由不充分的 `none` 决策。

决策和证据保存在变更工作区，跨压缩或交接保留。用错误假设率、加载耗时、重复读取、人工介入率和成本/延迟衡量效果；供应商缓存只是优化，不是正确性保证。
