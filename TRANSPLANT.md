# Transplant Guide

## 1. Conversational onboarding

Ask the Agent in the target repository to onboard Harness. It must locate the kit, classify the repository, and show a read-only plan before changing anything:

```bash
python3 /absolute/path/harness-engineering-kit/scripts/onboard.py \
  --project-root . --source-root /absolute/path/harness-engineering-kit --plan --json
```

After explicit user confirmation, the Agent runs the same command with `--apply`, then `--check`. `scripts/init.sh` is retained only as a compatibility forwarder for older automation.

Existing root adapters and project policy/profile files are preserved. Canonical methodology scripts/docs and the unified Engineering Skill are upgraded from the selected source version.

## 2. Configure

Replace every `{{...}}` value in:

- `AGENTS.md` and `CLAUDE.md`: project name only; keep them short.
- `ai.json`: project name, one-sentence summary, module routes, and canonical entrypoints only; keep it under 4096 bytes.
- `AI.md`: detailed root responsibilities, boundaries, local verification, and navigation.
- `docs/methodology/agent-policy.yaml`: real commands, paths, permissions, owners.
- `docs/methodology/profile.yaml`: risk/profile defaults and review metadata.
- `openspec/config.yaml`: the project's SDD conventions.

Do not move project facts back into root adapters or the Skill. Root `ai.json` must include `path: "."`. Add path `AI.md` files only where local responsibilities or navigation materially differ, record only local differences, and register every one in root `ai.json`. Keep commands and enforceable policy out of `ai.json`; they belong in `agent-policy.yaml`.

Existing root adapters are preserved during upgrade. Ensure their required-context section invokes `python3 docs/methodology/scripts/resolve_context.py <target-path> [<target-path> ...]` and reads the returned order exactly; `--check` rejects adapters that leave this route disconnected.

## 3. Verify

```bash
python3 /absolute/path/harness-engineering-kit/scripts/onboard.py \
  --project-root . --source-root /absolute/path/harness-engineering-kit --check --json
```

CI should also run:

```bash
python3 docs/methodology/scripts/check_agent_policy.py
python3 docs/methodology/scripts/check_context_docs.py
FITNESS_BASE_REF="$TRUSTED_BASE_SHA" python3 docs/methodology/scripts/check_fitness_protection.py
python3 docs/methodology/scripts/resolve_context.py .
python3 docs/methodology/scripts/check_profile.py
python3 docs/methodology/scripts/verify_skill.py engineering --platform claude --source-root /absolute/path/harness-engineering-kit
python3 docs/methodology/scripts/verify_skill.py engineering --platform codex --source-root /absolute/path/harness-engineering-kit
```

## 4. Operate

Resolve every target path before reading task code. Path routes load indexed context from parent to child. Repeated `--keyword <read_when>` arguments add semantic routes and fail closed when a keyword is not indexed.

Project Agents must treat `docs/fitness/**` as read-only. If a non-exempt change is genuinely needed, run `check_fitness_protection.py` to obtain its digest, stop, and request human approval. Approval variables must be injected by protected CI or a human operator and must never be committed or generated by pull-request code.

For each non-trivial implementation/refactoring request, create one change with `init_change.py` and explicitly record `native-selection`, `explicit-selection`, or `manual-fallback`. Complete `context-impact.json` before approval: route/topology/entrypoint changes require `ai.json`, while responsibility/boundary/invariant/dependency/contract/local-verification changes require the affected indexed `AI.md`. Advance only with `methodology_state.py`, bind approval with `approve_design.py`, and keep review/sync/archive evidence in the change directory.

Configure the optional or required Self-Refine inner loop in the Profile (`self_refine.policy` and `self_refine.max_iterations`). When required, include `self-refine-evidence.json` with the Review evidence; it records findings and resolutions but never replaces approval or deterministic gates.

Initialize the lesson memory directory and use `preflight_lessons.py` before Explore closes. Record failures with `record_failure.py`, propose reusable patterns with `create_lesson_candidate.py`, and activate only externally approved candidates with `approve_lesson.py`.

For production scope, create a production record with the same `change_id`, validate it with `check_production_readiness.py`, advance it with `change_state.py`, and close it only after deployment observation or rollback evidence. Engineering Archive remains blocked until then.

## 5. Upgrade

The conversational onboarding flow detects `current` and `legacy` states. It synchronizes canonical scripts/docs and both project-local Skill copies, preserves project-owned configuration and legacy entries, and records the receipt. Cleanup of old entries is a separate, explicitly approved change.
